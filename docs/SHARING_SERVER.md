# 약속 위치 공유 서버

이 코드는 **배포되지 않은 단일 프로세스용 프로토타입**입니다. Node.js 기본 모듈만 사용하며, 별도 패키지 설치 없이 로컬에서 실행할 수 있습니다. 정적 웹사이트 호스팅인 GitHub Pages만으로는 이 API를 실행할 수 없습니다.

## 무엇을 보호하고, 무엇을 보장하지 않는가

- 방은 추측하기 어려운 무작위 ID와 초대 토큰으로 보호합니다. 초대 링크를 받은 사람은 방에 참가하고 현재 참가자의 공유 위치를 볼 수 있습니다. **친구 계정이나 실명 인증은 없습니다. 링크를 전달받은 다른 사람도 참가할 수 있습니다.**
- 방 만들기와 참가하기만으로 현재 위치를 보내지 않습니다. 각 참가자가 별도로 위치 공유를 시작해야 합니다. 목적지와 약속 시각은 방 만들기 때 서버로 전송됩니다.
- 참가자별 토큰으로 자기 위치만 변경할 수 있습니다. 초대 토큰으로 다른 참가자의 위치를 변경하거나 방을 닫을 수 없습니다. 방 닫기는 호스트만 가능합니다.
- 서버는 각 참가자의 **마지막 위치 하나만** RAM에 보관합니다. 좌표 이력, 사용자 계정, 요청/접근 로그, 토큰 파일이나 데이터베이스를 만들지 않습니다. 재시작하면 모든 방과 세션이 사라집니다. 장기 토큰은 원문 대신 SHA-256 다이제스트로 보관하고 고정 길이 비교를 합니다.
- 위치는 30초부터 오래된 것으로 표시됩니다. 마지막 수신 후 90초가 되면 조회에서 제외하고 공유 권한 세대를 폐기합니다. RAM 정리는 매 요청과 1초 간격 정리 작업에서 수행됩니다. 실제 메모리 정리 시각은 이벤트 루프 지연의 영향을 받습니다. 다시 공유하려면 명시적으로 시작해야 합니다.
- 중지 요청이 서버에 도착하면 위치를 바로 지우고 이전 공유 세대를 폐기합니다. 늦게 도착한 이전 위치는 다시 나타나지 않습니다. **오프라인이면 중지 요청도 전달되지 않을 수 있어 마지막 수신 후 90초 숨김 정책에 의존합니다.**
- 방은 기본 6시간, 설정상 최대 24시간 유지됩니다. 호스트 포함 최대 8명입니다. 호스트가 나가거나 방을 닫으면 모두 접근할 수 없게 됩니다.
- 위치, 속도, ETA는 클라이언트가 보낸 값입니다. 서버가 GPS 진위, 도보 경로, ETA의 정확성이나 사람의 신원을 인증하지 않습니다. 이미 조회한 사람이 좌표를 복사하는 것을 막을 수 없습니다. 종단간 암호화가 아니므로 서버 운영자는 서버가 처리하는 데이터를 볼 수 있습니다.

## 로컬 실행

터미널 하나에서 프런트엔드를 실행합니다.

```sh
npm run dev
# http://127.0.0.1:3000
```

다른 터미널에서 API를 실행합니다.

```sh
node server/meeting-server.mjs
# http://127.0.0.1:8787
```

기본 프런트엔드 허용 Origin은 정확히 다음 두 개입니다.

- `http://127.0.0.1:3000`
- `http://localhost:3000`

두 독립 브라우저 세션으로 방 생성 → 초대 참가 → 각각 명시적 공유 시작 → 위치 조회 → 공유 중지 → 방 닫기를 시험할 수 있습니다. 로컬 HTTP 예외는 localhost만 허용합니다. 다른 휴대전화에서 PC의 사설 IP에 HTTP로 연결하는 구성은 지원하지 않습니다. 실제 휴대전화 GPS/두 기기 테스트에는 신뢰할 수 있는 HTTPS 프런트엔드와 API가 필요합니다.

자동 테스트에는 실제 위치 대신 가상 좌표만 사용합니다.

```sh
node --check server/meeting-server.mjs
node --test tests/server.test.mjs
```

## API 계약

모든 실제 동작은 `POST`, `Content-Type: application/json`을 사용합니다. CORS 사전 요청용 `OPTIONS`만 별도로 지원합니다. 응답은 JSON이며 캐시를 금지합니다. 요청 쿼리 문자열은 허용하지 않습니다.

인증값은 `Authorization: Bearer <token>` 헤더에 넣습니다. URL 경로나 쿼리, 분석 이벤트, 접근 로그에 인증값을 넣지 마세요. 초대 링크를 UI에서 만든다면 초대 권한은 URL fragment(`#` 뒤)에만 넣고, 읽은 뒤 주소창에서 즉시 제거해야 합니다. Fragment는 일반 HTTP 요청에 전송되지 않지만, 링크 전체를 복사한 사람과 브라우저 확장 프로그램 등은 읽을 수 있습니다. 참가자 토큰과 공유 세대 토큰은 초대 링크에 절대 포함하지 마세요.

방 ID와 참가자 ID는 24자 base64url, 토큰은 43자 base64url입니다. 멤버 토큰은 한 멤버 세션만 나타냅니다. 같은 초대로 재참가하면 별도 멤버가 생기므로 재시도/중복 클릭을 UI에서 제어해야 합니다. 생성/참가/공유 시작은 멱등 요청이 아닙니다.

### 1. 만들기

`POST /api/rooms/create`, 인증 없음:

```json
{
  "displayName": "민아",
  "destination": { "name": "만날 장소", "point": [37.5, 127.0] },
  "meetingAt": null
}
```

`201` 응답:

```json
{
  "roomId": "<room ID>",
  "inviteToken": "<invitation bearer token>",
  "memberId": "<host member ID>",
  "memberToken": "<host bearer token>",
  "expiresAt": 1800021600000
}
```

`displayName`은 앞뒤 공백 제거 후 1–24자, 목적지 이름은 1–120자입니다. 제어 문자와 양방향 표시 제어 문자는 거부합니다. `point`는 `[위도, 경도]`이며 유효 범위의 유한한 숫자 두 개입니다. `meetingAt`은 밀리초 Unix epoch 정수 또는 `null`입니다. 생략하면 `null`입니다. 방 만료 시각은 약속 시각과 별개이며 최대 24시간을 넘길 수 없습니다.

### 2. 초대로 참가하기

`POST /api/rooms/join`, **초대 토큰**으로 인증:

```json
{ "roomId": "<room ID>", "displayName": "준" }
```

`201` 응답은 `{roomId, memberId, memberToken, expiresAt}`입니다. 토큰을 가진 사람의 참가 자체가 초대 허용 범위이며, 별도 계정 인증이나 호스트 승인 대기열은 없습니다. 참가 전에는 위치를 볼 수 없고, 참가 후에는 공유 중인 참가자의 위치를 볼 수 있습니다.

### 3. 방 조회

이후 모든 요청은 **자신의 참가자 토큰**으로 인증하고 본문에 `{roomId, memberId}`를 포함합니다.

`POST /api/rooms/snapshot` 응답:

```json
{
  "roomId": "<room ID>",
  "serverTime": 1800000000000,
  "destination": { "name": "만날 장소", "point": [37.5, 127.0] },
  "meetingAt": null,
  "createdAt": 1800000000000,
  "expiresAt": 1800021600000,
  "hostMemberId": "<host ID>",
  "members": [
    {
      "id": "<member ID>",
      "name": "민아",
      "sharing": true,
      "lastSeenAt": 1800000000000,
      "stale": false,
      "position": {
        "point": [37.5001, 127.0001],
        "accuracy": 8,
        "speedMps": 1.2,
        "etaSeconds": 360,
        "recordedAt": 1800000000000,
        "receivedAt": 1800000000000
      }
    }
  ]
}
```

토큰은 조회 결과에 없습니다. 위치가 없으면 `position`과 `stale` 필드도 없습니다. `sharing:true`지만 첫 위치가 아직 없을 수도 있습니다. `lastSeenAt`은 인증된 조회/공유 동작 시 갱신되며 물리적인 활동이나 실시간 접속을 보장하지 않습니다.

`serverTime`으로 클라이언트의 시계 차이를 추정할 수 있습니다. `recordedAt`과 `receivedAt` 중 더 오래된 시각에서 30초가 지나면 `stale:true`입니다. 클라이언트는 네트워크가 끊긴 상태에서도 자체 타이머로 오래된 위치를 숨겨야 하며, 90초 이상 지난 위치를 계속 지도에 보여주면 안 됩니다. 권장 조회 주기는 화면이 보일 때 5초입니다.

### 4. 공유 시작

`POST /api/rooms/sharing/start`, 본문 `{roomId, memberId}`.

응답 `{ "shareEpoch": "<new random sharing generation token>" }`.

명시적 사용자 동의 후에만 호출하세요. 호출할 때마다 기존 위치를 지우고 새 세대를 만듭니다. 이전 세대의 지연 요청은 거부합니다. 시작 후 위치가 한 번도 오지 않아도 90초 후에 세대를 폐기합니다.

### 5. 위치 발행

`POST /api/rooms/position`:

```json
{
  "roomId": "<room ID>",
  "memberId": "<member ID>",
  "shareEpoch": "<current generation token>",
  "sequence": 1,
  "position": {
    "point": [37.5001, 127.0001],
    "accuracy": 8,
    "speedMps": 1.2,
    "etaSeconds": 360,
    "recordedAt": 1800000000000
  }
}
```

응답 `{ "accepted": true, "receivedAt": 1800000000000, "sequence": 1 }`.

- `sequence`는 같은 공유 세대 안에서 단조 증가하는 양의 안전한 정수여야 합니다. 재전송이나 순서가 뒤집힌 숫자는 거부합니다. 새 세대에서는 다시 1로 시작합니다.
- `recordedAt`은 현재 서버 시각에서 과거 30초 이내, 미래 5초 이내여야 합니다. 이미 받아들인 위치보다 과거인 기록도 거부합니다. 기기의 시계가 틀리면 공유가 거부될 수 있습니다.
- `accuracy`는 0–10,000m입니다. `speedMps`는 0–30m/s 또는 `null`, `etaSeconds`는 0–86,400초 또는 `null`입니다. 정지/불확실/경로 없음 상태에서는 ETA를 추측해 보내지 말고 `null`을 사용하세요.
- 서버가 덧붙이는 `receivedAt`이 보관 시간의 기준입니다. 과거 좌표를 현재 시각으로 위장하는 악의적인 클라이언트를 판별하지는 못합니다.
- 화면이 보일 때 새 GPS만 최대 5초 간격으로 보내는 구성을 권장합니다. 잠금/백그라운드 GPS는 이 서버로 해결되지 않습니다.

### 6. 중지, 나가기, 닫기

모두 본문 `{roomId, memberId}`입니다.

- `POST /api/rooms/sharing/stop` → `{sharing:false}`. 위치 삭제, 공유 세대 무효화. 이미 중지되어 있어도 성공합니다.
- `POST /api/rooms/leave` → `{left:true}`. 자기 멤버와 자격을 삭제합니다. 호스트이면 방도 닫히고 `{left:true,closed:true}`를 반환합니다.
- `POST /api/rooms/close` → `{closed:true}`. 호스트만 가능합니다. 모든 멤버/초대 접근이 즉시 끝납니다.

클라이언트는 시작/중지 요청이 뒤집히지 않게 세대 또는 직렬화를 관리해야 합니다. 사용자가 취소한 뒤 늦은 시작 응답이 돌아오면 다시 중지해야 합니다. 위치 발행은 서버의 세대 검증이 중지 후 재등장을 차단합니다. 브라우저 종료에 의존한 `keepalive` 요청은 전송 보장이 아닙니다.

### 오류

오류 응답 형태는 `{ "error": { "code": "...", "message": "..." } }`입니다.

- `400`: 잘못된 JSON/필드
- `401`: 잘못되었거나 사라진 초대/멤버 자격
- `403`: 허용되지 않은 Origin 또는 호스트 전용 동작
- `404`: 방 만료/닫힘/잘못된 ID 또는 존재하지 않는 경로
- `405`: POST가 아닌 메서드
- `409`: 방 정원 초과, 공유 중지/만료, 세대 불일치, 재전송/순서 오류
- `413`: 8KiB를 넘는 요청 본문
- `415`: JSON이 아니거나 압축된 요청
- `422`: 오래되었거나 미래의 위치 시각
- `426`: 허용되지 않은 평문 HTTP
- `429`: 요청 한도 초과
- `503`: 서버 방/요청 추적 용량 한도

모든 `409`가 방 만료를 뜻하지는 않습니다. `sharing_inactive`는 해당 공유 세대가 끝났다는 뜻이고, `sequence_replayed`는 해당 위치만 거부되었다는 뜻입니다. 자동으로 사용자 공유 동의를 다시 켜지 마세요.

## 설정

| 환경 변수 | 기본값 | 의미 |
|---|---|---|
| `HOST` | `127.0.0.1` | Node 바인딩 주소 |
| `PORT` | `8787` | 포트, 1–65535 |
| `ALLOWED_ORIGINS` | 위의 localhost 두 Origin | 쉼표 구분 정확한 Origin. 와일드카드/경로/끝 슬래시 금지 |
| `TRUSTED_PROXY_IPS` | 비어 있음 | HTTPS 종료 프록시의 정확한 IP 주소 목록. CIDR/와일드카드 불가 |
| `ROOM_TTL_MS` | `21600000` | 방 수명. 1000–86400000ms |
| `MAX_ROOMS` | `1000` | 프로세스당 방 한도. 1–5000 |

`ALLOWED_ORIGINS`는 운영 시 HTTPS만 허용합니다. HTTP는 정확한 localhost 주소에만 허용됩니다. GitHub Pages 저장소 사이트가 `https://example.github.io/my-walk/`라면 Origin은 `https://example.github.io`입니다. Origin은 경로로 구분되지 않으므로 같은 Origin의 다른 페이지도 같은 브라우저 출처로 취급됩니다.

기본 한도는 연결 IP당 분당 300요청, 시간당 10개 방 생성, 분당 30회 참가 시도, 멤버당 분당 180요청 및 분당 60회 위치 발행입니다. JSON 본문은 8KiB, 헤더는 8KiB, 본문 수신 제한은 10초입니다. 한도와 서버 용량은 최소한의 방어일 뿐 전문적인 DDoS 대응이 아닙니다. `X-Forwarded-For`를 클라이언트 IP로 신뢰하지 않습니다. 따라서 프록시 뒤에서는 IP 한도가 프록시의 모든 사용자에게 합산되며 운영 프록시의 별도 사용자별 제한이 필요합니다.

## HTTPS 배포 준비 예시: 직접 관리하는 역방향 프록시

아래는 구성 지침이며 실제 서버 생성/배포/도메인 연결/인증서 발급은 수행하지 않았습니다.

1. 신뢰할 수 있는 호스트에 지원 중인 Node.js를 설치하고 애플리케이션 코드를 배치합니다.
2. Node API는 루프백에만 바인딩합니다. 외부에서 Node 포트에 직접 들어오지 못하게 합니다.
3. 신뢰할 수 있는 HTTPS 역방향 프록시만 API로 연결합니다. TLS 인증서를 준비하고 HTTP는 HTTPS로 리다이렉트합니다.
4. 프록시는 클라이언트가 보낸 `X-Forwarded-Proto`를 전달하지 않고 직접 `https`로 **덮어써야** 합니다. HTTPS 리스너만 Node로 프록시하세요.
5. 실제 프런트엔드의 Origin만 허용하고, 프런트엔드에도 정확한 API 주소를 설정합니다.

예시 환경 변수:

```sh
HOST=127.0.0.1 \
PORT=8787 \
ALLOWED_ORIGINS=https://walk.example \
TRUSTED_PROXY_IPS=127.0.0.1,::1 \
node server/meeting-server.mjs
```

Nginx의 이미 준비된 HTTPS `server` 블록에 들어갈 최소 예시:

```nginx
# 실제 TLS 인증서, 도메인, 방화벽, 요청 제한은 운영자가 별도로 구성합니다.
location /api/ {
    access_log off;
    client_max_body_size 8k;
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header Authorization $http_authorization;
    proxy_read_timeout 15s;
}
```

운영 프록시, 호스팅, APM, 오류 수집기의 요청 본문/Authorization/응답/위치 로그를 끄거나 제거 정책을 검증하세요. 이 애플리케이션이 로그를 안 남긴다는 사실은 호스팅 업체, 브라우저, 프록시, 백업, 프로세스 덤프까지 보장하지 않습니다. 사용자 좌표나 토큰으로 작동 확인 스크린샷/로그를 만들지 마세요.

호스팅 플랫폼이 `0.0.0.0:$PORT` 바인딩을 요구하면 해당 값에 맞춰 바인딩할 수 있지만, 검증한 프록시의 정확한 IP와 헤더 덮어쓰기 계약, 내부 포트 차단을 먼저 확인해야 합니다. 알 수 없는 프록시를 모두 신뢰하도록 우회하지 마세요. 플랫폼별 동적 프록시 신뢰 방식은 현재 구현에 포함되어 있지 않습니다.

## 실제 서비스 전 남은 일

- 서비스 소유 계정, 도메인, TLS, 호스팅, 프록시 신뢰, 상태 확인, 장애 대응, 운영 로그/메모리/백업 정책 검증
- 실제 두 기기와 iPhone Safari의 권한 거부, 화면 잠금, 네트워크 전환, 시계 차이, 중복 탭, 재접속 테스트
- 친구 인증, 지속적인 친구 목록, 개별 초대 취소/교체, 강퇴/차단, 신고/악용 대응 기능 없음
- 방 생성/참가의 멱등 키, 닉네임 중복/위장 방지, 계정 복구 없음
- 단일 프로세스만 지원. 여러 인스턴스/자동 확장/재시작 간 공유 상태가 없으며, 이 설계를 그대로 다중 서버에 배포하면 방이 보이지 않을 수 있음
- 링크 권한 방식에 대한 보안 검토, 취약점/과부하 테스트, 위치 개인정보 취급과 안내/동의 검토
- E2E 암호화 없음. 참가자가 이미 받아 본 위치를 회수할 수 없음. 위치·속도·ETA 위조 검증 없음
- 호스트 닫기/나가기로 전체 접근을 끝낼 수 있으나 개별 친구 관계나 독립적인 초대 링크 회수는 미구현

자동 테스트 통과는 공개 배포의 보안 인증이나 실제 GPS 검증이 아닙니다.
